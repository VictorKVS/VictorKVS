DevSafe

Developer safety tooling intended to reduce code-loss risk through Git history, local backup and controlled automation.

Problem

Developers can lose work through uncommitted changes, local filesystem failure or accidental deletion. DevSafe explores a bounded two-layer protection model: repository history plus local recovery copies.

Verified today

The repository contains concrete Python implementation areas for backup, commit scheduling, Git operations, project management, runtime control, a state machine and filesystem watching. It also contains a dedicated test tree with unit/integration-style tests for backup, scheduler behavior, Git safety, project management, runtime integration, state-machine behavior and watcher integration.

Evidence boundary

The current README labels a broad MVP including Windows GUI, automatic commits/pushes, backup, secret avoidance and multi-project management. The repository evidence supports meaningful implementation, but this audit has not yet demonstrated a clean-host end-to-end run of the complete advertised workflow. Therefore the public status remains partial implementation, not verified MVP.

Architecture

watcher → debounce/runtime → commit scheduler → git agent with a parallel backup path, coordinated by project management and fail-safe state control.

Promotion gate

Promote toward MVP only after a reproducible setup proves: watched file change → safe local snapshot → expected Git action → remote push when configured → restore path → secret/ignored-file negative tests → clean test run.

Ecosystem role

DevSafe fits the engineering-safety / DevSecOps product layer. It can later consume evidence and policy from KNOWLEDGE_CORE and can be orchestrated by higher-level MindForge/PX00 workflows without changing PX00 itself.

Roadmap claims are intentionally separated from verified implementation evidence.
