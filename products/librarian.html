Librarian AI

Knowledge-ingestion and analysis agent for turning heterogeneous documents into structured, searchable and graph-oriented engineering knowledge.

Problem

Engineering and intelligence work receives information as PDFs, DOCX, text, HTML and outputs from other agents. The useful entities, metadata, relationships and provenance need a repeatable path into relational, vector and graph-oriented stores.

Observed implementation evidence

The repository currently documents document ingestion, entity extraction, graph tooling, visualization, LLM adapters, relational storage and vector-store integration. Repository history also records a completed minimal document-processing/indexing core and later GigaChat integration work.

This page reports observed repository evidence; it does not promote every roadmap item to shipped functionality.

Architecture direction

Documents / OSINT agents → Librarian processing → relational + vector + graph knowledge → LLM / analyst consumers.

The public portfolio positions Librarian AI as a product-facing knowledge-ingestion component adjacent to, but not identical with, the protected evidence-backed KNOWLEDGE_CORE layer.

Current maturity

SHOWCASE CANDIDATE. The repository has substantial implementation history, but the portfolio still needs to verify the present runnable entry point, dependency installation, tests and reproducible demo before upgrading the label to MVP.

Known repository lineage

Librarian-AI is currently the stronger canonical candidate. The older librarian_ai repository is retained as a non-destructive merge candidate until unique code and history are compared.

Next evidence gate

Verify quick start, current CLI/API entry point, supported document formats in executable code, automated tests, storage dependencies and one reproducible end-to-end example.
