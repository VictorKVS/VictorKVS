SecGraph

Knowledge-driven security audit, intelligence and pentest product line built around explicit relationships between requirements, threats, vulnerabilities, assets, controls, evidence and analyst decisions.

Problem

Security knowledge is usually fragmented across regulations, threat models, audit evidence, OSINT findings, vulnerability tooling and reports. SecGraph aims to turn those fragments into an inspectable graph that can support repeatable audit and security-analysis workflows.

What is verified today

  • Product architecture and roadmap exist.
  • KB Core specification exists in docs/001_kb_core_spec.md.
  • KB Core test specification exists in docs/002_kb_core_tests.md.
  • A backend dependency file exists.
  • The current backend tree also contains a committed .venv, which is a repository-hygiene issue to be resolved in a controlled pass.

What is not yet claimed

  • No verified runnable FastAPI application path in the inspected source tree.
  • No verified database migrations / ORM implementation.
  • No verified working Knowledge Graph API or dashboard.
  • No verified executable automated test suite.
  • No verified reproducible Docker quick-start.

Architecture direction

Security KB / KNOWLEDGE_CORE → SecGraph knowledge graph → audit / OSINT / pentest workflows → evidence-linked reporting

PX00 remains a protected autonomous engineering-intelligence layer. SecGraph is presented as a product output, not as part of PX00 cleanup.

MVP evidence gate

  1. Clean reproducible source tree.
  2. Quick-start from a clean environment.
  3. Database schema and migrations.
  4. Working node / edge / audit-log implementation.
  5. API matching the KB Core specification.
  6. Executable tests.
  7. Documented limitations and security assumptions.
  8. One end-to-end audit or knowledge-graph scenario.

Roadmap ≠ shipped

The intended roadmap includes KB Core, web/API inspection, OSINT ingestion, audit and controlled pentest automation, followed by AI-assisted analysis and evidence-linked reporting. These are roadmap directions until repository evidence proves them runnable.
